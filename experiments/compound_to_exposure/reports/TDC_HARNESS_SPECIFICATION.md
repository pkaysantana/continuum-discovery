## Exact split behaviour and local evidence limit

DOCUMENTED: the dataset loader's `get_split()` defaults are ordinary loader defaults; they do not reproduce the fixed test membership of the benchmark group. Its random branch calls `create_fold()`: test sampling uses the supplied seed, validation sampling from the remainder uses fixed `random_state=1`, and the remaining records become training (`tdc/utils/split.py:10–33`). Its optional `method="scaffold"` calls the scaffold function described below (`single_pred_dataset.py:166–167`). Neither path should be substituted for the group API when claiming group benchmark reproduction.

DOCUMENTED: the group reads `<path>/admet_group/clearance_microsome_az/train_val.csv` and `test.csv` (`base_group.py:137–155`). The default train/validation splitter uses `create_scaffold_split(train_val, seed, frac=[0.875,0.125,0.0], entity="Drug")` (`base_group.py:90–135`).

`tdc/utils/split.py:create_scaffold_split`, lines 104–192, specifies:

1. Compute atomic Murcko scaffold SMILES with `includeChirality=False` directly on each supplied SMILES (lines 139–143). There is no largest-fragment rule and no `__ACYCLIC__` sentinel in this implementation; empty scaffolds naturally share the empty-string key.
2. Omit structures that cause an RDKit exception and reduce the effective N (144–151). Training and validation capacities use integer truncation of effective N times the requested fractions.
3. Collect scaffold groups in encounter order, separate big from small using `len(group) > val_size/2 or len(group) > test_size/2`, shuffle each list with Python `random.Random(seed)`, and concatenate big then small (132,154–166).
4. For `frac[2] == 0`, greedily put each whole group into training if it fits the training capacity; otherwise put it in validation (168–175). Validation is not capped at its nominal fraction, so realised fractions can depart from 87.5/12.5. There is no SHA-256 assignment and no grouped inner-CV or model-selection procedure supplied by this harness.

## Metric, direction and evaluator behaviour

DOCUMENTED: `admet_metrics["clearance_microsome_az"] = "spearman"` (`metadata.py:535`). `Evaluator.assign_evaluator()` selects `scipy.stats.spearmanr` (`tdc/evaluator.py:413–418`); `Evaluator.__call__()` converts both inputs to NumPy arrays and returns element `[0]`, the signed correlation coefficient (`evaluator.py:471–488`). The p-value is discarded. The call supplies no special tie, missing-value or constant-input handling; it inherits SciPy defaults. No log transform, censor-aware ranking, absolute-value transform or sign inversion occurs in this evaluator.

INFERRED from the signed rank-correlation metric: larger positive Spearman is better, with +1 indicating perfect rank agreement. The evaluator returns a statistic; it does not implement pipeline optimization or a separate maximize/minimize switch.

DOCUMENTED: group `evaluate()` defaults to `testing=True`, reads test labels in `test.csv` row order, selects the metadata metric automatically, and returns `{"clearance_microsome_az": {"spearman": score}}`, rounding the score to **three decimal places** (`base_group.py:157–188`). Predictions must align positionally with test rows; no molecule-ID merge is performed. A standalone `Evaluator` does not apply this three-decimal rounding.

Source defect relevant to future use: the `testing=False` branch requires `benchmark`, then references `true` without defining it (`base_group.py:206–216`). Static inspection finds no local/global definition of that variable. That branch cannot be assumed to provide working validation evaluation. It was not invoked, repaired or substituted here. `save_dict=True` is an unused parameter in this implementation. A `target_class` column triggers additional subset evaluations (`base_group.py:190–204`); whether the absent group data contain that column is not verified.

## Seeds and aggregation: what is prescribed, demonstrated and enforced

DOCUMENTED: the bundled official README's leaderboard code framework explicitly loops over **[1, 2, 3, 4, 5]**, uses each as the train/validation split seed, accumulates test-prediction dictionaries, and calls `evaluate_many()` (`README.md:223–247`, specifically 230,236,246). This is a generic ADMET-group example using Caco2_Wang, not a clearance-specific executable seed requirement. The deprecated group class docstring also demonstrates these same five seeds (`benchmark_deprecated.py:72–87`). Thus saying the five-seed convention has *no package evidence* would be incorrect.

DOCUMENTED: the callable group splitter has **one required caller-supplied seed**, no default and no restriction to that list (`base_group.py:90`). It does not set estimator seeds. `evaluate_many(preds, save_file_name=None, results_individual=None)` checks for **at least five** prediction dictionaries, not exactly five or five distinct seeds (`base_group.py:218–238`). It does not run the splits/models itself, store seed identities, or verify their values. Fewer than five inputs returns a `ValueError` object rather than raising it.

DOCUMENTED: mean/SD aggregation **is part of the shipped harness**, not an unsupported invention. By default, `evaluate_many()` calls `evaluate()` once per prediction dictionary; then it computes `np.mean` and `np.std` with default **ddof=0** across the per-run scores, and rounds both to three decimals (`base_group.py:239–257`). Its actual return is `{"clearance_microsome_az": [mean, std]}`. Because `evaluate()` already rounds, the default aggregate operates on three-decimal per-run scores. Passing `results_individual` bypasses those evaluator calls. `save_file_name` is unused here. The deprecated root API likewise implements mean/SD for ADMET (`benchmark_deprecated.py:445–470,521–533`). SD across runs is not a confidence interval.

**Correction to SAP wording:** “across its prescribed seeds” conflates the documented five-seed example with a code-enforced seed set. Accurate factual wording is: “PyTDC 1.1.15's bundled ADMET leaderboard example uses split seeds [1,2,3,4,5]. The split API requires a caller-supplied seed; `evaluate_many()` aggregates at least five supplied runs using mean and population SD, and does not enforce seed identities.” Explicitly adopting that example as the v2 benchmark's frozen run convention remains a protocol decision.

## Other material defaults

- Single-dataset loading defaults to target `Y`, removes duplicate columns and missing-target rows, and returns source structure/label/ID fields (`utils/load.py:378–403,427–430`). Format conversion is off unless requested (`single_pred_dataset.py:97–121`); no automatic clearance log transform or restoration of relation qualifiers occurs. The verified single-dataset boundary numbers remain bare numbers in that artifact. Its identity with the unacquired group data has not been established.
- Group construction can download/extract files; an existing group directory is trusted as a local copy, with no content-hash check in that wrapper (`utils/load.py:249–276`). A reproducible benchmark therefore needs the actual artifact hashes in addition to the package pin. No constructor was invoked in this task.
- Group loading uses pandas CSV inference; input row order feeds scaffold encounter order and test-prediction alignment (`base_group.py:107–123,146–150,179–187`; `utils/split.py:134–166`). Package/dependency versions and input bytes matter.
- The package supplies retrieval, splitting and evaluation. It does not prescribe this project's representations, estimators, tuning, preprocessing, model-selection policy or estimator seeds. Those cannot be delegated to the words “official harness.”

The group API, scaffold split method, Spearman metric and mean/population-SD aggregation are established from source. Group-data membership/fractions and a compatible frozen execution environment remain open; run-seed adoption must be explicit. The SAP was not changed.
